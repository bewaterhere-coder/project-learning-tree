# M2.4 — Product Workspace & UI Foundation

## Goal

Let a learner create, switch, archive, and restore their own learning projects, add core questions, and keep that work across reloads. At the same time, replace the demo chrome with a tokenized product UI: light, dark, and system themes.

## Workspace organization

```text
Project archive = Workspace semantics
Project completion ≠ archive
completePass remains a Domain learning operation
archiveProject only sets ProjectWorkspace.archived = true
```

`LearningWorkspace.selectedProjectId` may be `null`. That is the production first-run state and the state after the last active project is archived.

Production App:

```text
semantic store missing or unreadable
→ createWorkspace([])
→ Product Empty Workspace
```

Demo fixtures remain for tests and explicit `initialWorkspace` injection. They are not the production fallback.

## Persistence

```text
DomainSnapshots use dedicated semantic persistence
UI preferences never contain DomainSnapshot
```

- Semantic store: `plt.workspace.semantic.v1` — snapshots, `archived`, `selectedProjectId`
- Preferences: `plt.workspace.layout.v2` — layout, locale, `colorScheme` (migrates v1)
- Theme hint: `plt.workspace.theme` — boot cache only

`workspace.shell.colorScheme` is the authoritative theme. After hydration, a mismatched hint is rewritten.

Semantic writes happen only for create / archive / restore / select / successful Domain snapshot mutation. Node drag, viewport, sidebar, inspector, locale, and theme write preferences only.

## UI foundation

Light, dark, and system share semantic tokens. Selected (focus ring / elevation) is visually distinct from active-learning (tint / left rail).
