# M2.5 — QA Harness & Browser Acceptance Foundation

## Goal

Add a maintainable Playwright acceptance layer so later milestones can be verified against real browser behavior, not only Vitest.

This milestone is infrastructure-first. It does not exhaustively test the product.

## Responsibility boundary

```text
typecheck
→ Vitest (domain, reducers, persistence contracts, component tests)
→ build
→ Playwright Chromium (real-browser workflows and integration)
→ acceptance review
```

Use Vitest for cheap deterministic behavior. Use Playwright for production-boot workflows, real localStorage, real reload, and real XYFlow.

`npm test` remains Vitest-only and must not launch a browser.

## Production boot (unchanged)

```text
missing / invalid semantic store
→ createWorkspace([])
→ selectedProjectId = null
→ Product Empty Workspace
```

Demo fixtures stay test/development-only. Playwright uses `src/ui/main.tsx` with no test API, no `window.__TEST__`, and no demo fallback.

## Harness layout

```text
playwright.config.ts
tsconfig.e2e.json
e2e/fixtures/     extended test, storageState seeding, console guard
e2e/helpers/      localStorage, project identity, console allowlist
e2e/specs/        smoke / acceptance
e2e/visual/       Linux-canonical screenshots
```

Chromium is the only required CI browser. Firefox and WebKit are out of scope for M2.5 (extra runtime, snapshot matrix, and XYFlow engine flake without a user-visible non-Chromium target).

## Deterministic state

Each test gets a fresh browser context.

- Empty tests leave `plt.*` keys unset so production hydration creates an empty workspace.
- Seeded tests inject `plt.workspace.semantic.v1` (and optionally prefs) once through Playwright `storageState`.
- Do not use `addInitScript` to write semantic state. That would reapply on `page.reload()` and fake persistence.

Reload contract:

```text
seed once (or start empty)
→ run app
→ mutate through UI
→ page.reload()
→ verify persisted result
```

Keys:

- Semantic: `plt.workspace.semantic.v1`
- Preferences: `plt.workspace.layout.v2`
- Theme hint: `plt.workspace.theme`

## Selector policy

1. Existing `data-testid` for chrome.
2. User-authored project names and questions for instance identity.
3. `data-node-id` on the real `LearningNode` for canvas nodes.
4. Never CSS hierarchy, XYFlow implementation classes, or translated English chrome.

## Runtime error invariant

`e2e/fixtures/test.ts` fails the test on unexpected `console.error`, `pageerror`, and page crash. Ordinary `console.warn` is not a failure.

Whitelist entries live in `e2e/helpers/console.ts` and must name an exact unavoidable message. Do not ignore all ResizeObserver, React, or console.error output.

## Visual snapshots

Playwright native `toHaveScreenshot` only. No Percy.

Surfaces:

1. Product Empty Workspace
2. Product shell after project creation, before XYFlow canvas content

Canonical environment is Linux CI (`ubuntu-latest`). Do not treat macOS/Windows output as the baseline. The `project-empty-shell` PNG was taken from a GitHub Actions `ubuntu-latest` Playwright actual after a cloud-agent Linux baseline mismatched on font rasterization (same layout, extra text surfaces more glyph/AA pixels). Keep `maxDiffPixelRatio` at `0.01`. Local visual runs:

```bash
E2E_VISUAL=1 npm run test:e2e
npm run test:e2e:update-snapshots
```

Prefer updating snapshots from Linux (CI or `mcr.microsoft.com/playwright` matching the installed Playwright version).

## Artifacts

A failed acceptance test must leave evidence. CI uploads `playwright-report/` and `test-results/` on failure (`if: failure()`), including traces, failure screenshots, and visual diffs.

Inspect in this order:

1. GitHub Actions log
2. HTML report (`npx playwright show-report`)
3. `test-results/**/trace.zip` (`npx playwright show-trace`)
4. Failure screenshot
5. Visual expected / actual / diff

Video is off. Traces use `retain-on-failure` so a failed test always leaves `trace.zip` even without a retry.

Artifact contract was verified locally by inserting a temporary failing assertion. The run produced `test-results/**/test-failed-1.png`, `trace.zip`, `error-context.md`, and `playwright-report/`. The probe was removed before merge. CI uploads the same directories with `if: failure()` so a failed `test:e2e` step cannot skip the upload.

## Future regression / agent reuse

Do not add MCP or a browser-agent dependency in M2.5. Reuse this harness later:

```text
start preview server
→ explore in Chromium
→ keep screenshot / trace
→ convert a confirmed bug into a deterministic e2e/*.spec.ts
```

Regression rule:

```text
reproduce bug
→ fix bug
→ add a Playwright regression test when the bug is browser/integration-level
→ retain it permanently
```
