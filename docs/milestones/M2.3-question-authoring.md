# M2.3 — Question Authoring Semantics

## Goal

Let a learner add questions to their own learning tree and decide which of those questions must be answered before a parent can close.

M1 Domain Engine remains the authority for tree semantics. M2.2 close-readiness and localization remain the Inspector/error pattern.

## Formal relationships

```text
childIds = all direct children

blockingChildIds
= completion dependency subset of childIds
```

```text
普通子问题
= 已进入学习树的 LearningNode
= parent.childIds contains it
= parent.blockingChildIds does not contain it
= unfinished state does not block parent close
```

```text
需要先解决的子问题
= 已进入学习树的 LearningNode
= parent.childIds contains it
= parent.blockingChildIds also contains it
= unfinished state blocks parent close
```

```text
FrontierItem
= the user already decided to keep the question for later
= not a LearningNode
```

```text
Question Candidate
= a future Application-level proposal from the user or AI
= cannot mutate DomainSnapshot before the user accepts it
```

Blocking is not a lifecycle. Ordinary children and blocking children are both real `LearningNode`s.

## Domain operations

- `createChild` — materialize an ordinary child from `open` / `active` / `parked` parents
- `createBlockingChild` — unchanged intent; parent must be `active`
- `markChildBlocking` / `unmarkChildBlocking` — relationship conversion; idempotent; reject closed parents
- `promoteFrontierItem({ placement })` — `root` | `child` | `blockingChild`

`createChild` and `createBlockingChild` both reject blank `question` / `goal` and persist trimmed values.

Relationship invariants are guaranteed by those mutation operations. They are not enforced by a global `ok()` tree walk.

## Application / UI

Inspector inline authoring:

```text
Add a sub-question
→ question + goal
→ optional “must be answered first” only while the parent is active
→ createChild or createBlockingChild
```

Existing children can later be marked or unmarked as “Must be answered first”.

Authoring errors stay next to the authoring controls. Field errors stay next to fields. The global banner is only for unattributed system errors.
