# M2.1 — Multi-Project Learning Workspace

## Goal

Let a learner browse and switch multiple Learning Projects in one workspace, with independent DomainSnapshots and per-project tree/inspector chrome, without changing M1 Domain semantics.

M1 Domain Engine remains frozen. M2 Tree UI remains the per-project canvas.

## Core invariants

```text
DomainSnapshot is the single source of truth for learning state.
Workspace layout is the single source of truth for UI chrome.
```

```text
UI / Infrastructure
        ↓
Workspace
        ↓
Application
        ↓
Domain
```

Forbidden:

- Changing M1 Domain types or operations to support multiple projects
- Sharing `activeStack` / Current Focus across projects
- Writing layout, locale, or sidebar state into `DomainSnapshot`
- Persisting `DomainSnapshot` to localStorage
- Drag-to-reparent, edge creation, or Domain operations from node drag

## Deliverables

- `src/workspace` multi-project session (`LearningWorkspace`)
- Global Project Sidebar (collapse, resize, completion / active / blocked)
- Per-project Inspector overlay (open, close, resize)
- Layout-only LearningNode dragging
- Auto layout only for nodes without a saved position
- localStorage persistence for workspace UI preferences only
- `selectProjectSummary` derived selector
- `zh-CN` / `en-US` catalogs; locale is workspace-global
- Two-project demo fixture
- Acceptance tests listed below

## Workspace model

```ts
interface LearningWorkspace {
  projects: ProjectWorkspace[];
  selectedProjectId: ProjectId;
  shell: {
    projectSidebarOpen: boolean;
    projectSidebarWidth: number;
    locale: "zh-CN" | "en-US";
  };
}

interface ProjectWorkspace {
  projectId: ProjectId;
  snapshot: DomainSnapshot;
  layout: {
    nodePositions: Record<NodeId, { x: number; y: number }>;
    viewport: { x: number; y: number; zoom: number };
    inspectorOpen: boolean;
    inspectorWidth: number;
  };
}
```

Selecting a project changes only `selectedProjectId`. It must not clone or mutate another project's `DomainSnapshot`.

## Node dragging

- `nodesDraggable: true`
- `nodesConnectable: false`
- No `onConnect` / edge creation
- `onNodeDragStop` updates `layout.nodePositions` and persists UI prefs
- DomainSnapshot reference and content stay unchanged
- Parent/child relationships stay unchanged

Position priority:

```text
saved user node position
  → auto layout position
```

Auto layout must not overwrite a saved user position on rerender or project switch.

## Persistence

In scope: localStorage for workspace UI preferences (`version`, shell, per-project layout).

Out of scope: Domain persistence, Dexie, IndexedDB, accounts, sync.

Invalid JSON, wrong version, or DomainSnapshot-shaped payloads fall back to defaults.

## Acceptance scenarios

1. Workspace can contain multiple projects.
2. Clicking Project B shows Project B's tree.
3. Project A and Project B Active Stacks are independent.
4. Project A and Project B Current Focus are independent.
5. Switching projects does not mutate the other DomainSnapshot.
6. Returning to a project restores node positions.
7. Returning to a project restores viewport / zoom.
8. Sidebar shows a completion visual.
9. Sidebar shows the active question.
10. Sidebar shows a blocked signal.
11. Sidebar can collapse and restore.
12. Inspector is an overlay, not a fixed layout column.
13. Inspector can close.
14. Closing Inspector does not change Current Focus.
15. Reopening Inspector still shows the current Focus.
16. Inspector width can be adjusted and restored.
17. Workspace state stays separate from DomainSnapshot.
18. i18n covers Project Sidebar and Inspector chrome.
19. LearningNode is draggable.
20. Drag does not change DomainSnapshot.
21. Drag updates `nodePositions`.
22. Reloading workspace preferences restores position.
23. Project switch restores position.
24. Auto layout does not overwrite a user position.
25. `nodesConnectable === false`.
26. Drag does not change parent/child.
27. Sidebar resize state survives project switch.
28. Locale survives project switch.
29. Corrupted layout storage falls back to defaults.
30. Persisted layout does not contain DomainSnapshot.

## Constraints

- No AI Chat, LLM providers, GitHub ingestion, Domain persistence, auth, backend, RAG, or collaboration.
- No Frontier UI, Focus Panel conversation, Reopen UI, or create-blocking-child UI.
- No drag-to-change-parent and no free-form mind-map editing.
- Do not start M3.

## Exit criteria

M2.1 is complete only when the acceptance scenarios pass, M1 and M2 tests still pass, DomainSnapshot remains the only business source of truth, and workspace UI preferences remain outside DomainSnapshot.
